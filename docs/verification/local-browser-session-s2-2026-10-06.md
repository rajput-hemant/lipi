## Confirmed failures and fixes

1. Quota rejection had no browser warning. Reproduce with the seeded 500-block page, an editor role, and Enter inside the editor. Rejection originates at `lib/realtime/block-quota.ts:84`, but Hocuspocus's document-close path falls back to `Reset Connection` unless the error exposes `reason`. Before the fix, `components/document-editor/document-block-editor.tsx:160` listened only to status/synced events and never showed the rejection. Fix: `lib/billing/errors.ts:4` exposes a stable quota reason, and `document-block-editor.tsx:166` handles the block reason. Alert at line 246, editing gate at line 236. Production change is under 30 added lines. Regression runs a real Hocuspocus server/provider and checks the delivered rejection reason; browser retest checks warning, disabled editing, unchanged stored quota and reload recovery. No automatic rollback was added; unsaved local content remains visible until explicit reload.

2. Access-revoked screen emits a Base UI console error. Reproduce by removing the editor while its page is open, then inspect console. `components/workspace-access-revoked.tsx:24` rendered Next Link with default native-button mode. Fix only the application composition with `nativeButton={false}`; protected shadcn source is unchanged. Regression mounts real component/Button, checks dashboard href and absence of console errors, and unmounts cleanly. Browser reload showed no console errors.

Both regression tests were mutation-checked. Removing the quota `reason` getter made the protocol test fail (`Reset Connection` received instead of the quota reason). Removing `nativeButton={false}` made the component test fail with the reproduced Base UI warning. Fixes restored afterwards.
